# データグラフの作図規約
目的と優先順位
グラフは、読者が測定値、変化、差、ばらつきを正確に読み取れるように作る。見た目の装飾より、データへの忠実さと判読性を優先する。

優先順位は (1) データを歪めない (2) 軸・値・単位を読み取れる (3) 比較対象を区別できる (4) 図全体で表現を統一する (5) 見た目を整える、の順とする。

規則には「必須」「原則」「条件付き」を設ける。掲載先の論文誌・授業・研究室の指定があれば、その規定を優先する。
必須規則
- 軸の意味を記す。 各軸に測定量・評価指標の名称を明記する。専門家に通じる略号だけを置いて説明を省略しない。単位のある量は軸名に単位を添える（例：`遅延 [ms]`）。無次元量は必要に応じて 割合 [-]、`成功率 [%]` などとする。
- 目盛りを読めるようにする。 主要目盛りの数値は目盛り位置と明確に対応させる。ラベルが重ならないよう間隔と桁数を調整する。主要目盛りはおおむね4〜9個から検討するが、固定ルールではない。
- 目盛りの数値が一意に決まるようにする。 異なる目盛りが丸めによって同じ表示になってはいけない。`0.00085` など長い数値は科学表記や軸の倍率表示で簡潔にできる。指数表記は原則 ×10ⁿ とし、論文図の軸にソフトウェア由来の e-11 をそのまま残さない。
- 測定値とモデル・補間・推定を区別する。 実測点は視認できるマーカーで示す。近似曲線や理論線は、実測値であるかのように描かず、凡例・キャプションで意味を記す。データを勝手に補間・平滑化・削除・修正しない。
- 比較系列を識別可能にする。 複数系列には凡例または直接ラベルを付ける。色だけを識別手段にせず、必要に応じて線種とマーカーを併用する。
- 図の外に情報を欠落させない。 点、エラーバー、凡例、軸ラベル、目盛りラベルが欠けたり切れたりしないようにする。軸ラベルは原則プロット領域の外に置く。
- 範囲と尺度を正しく設定する。 まず軸の範囲が実験設計・定義・物理法則などによって決まっているか確認する。範囲が確定している数量軸は原則としてその端点に一致させ、見た目のためだけに外側へ余白を設けない。範囲が確定していない軸はデータと目的に応じて余白を設定する。軸切断、非ゼロ起点、対数軸は誤解を生まないよう明示する。棒グラフは原則ゼロを基準とする。
- 画像自体は最小限にする。 図番号、タイトル、説明的キャプション、詳細な実験条件は原則としてLaTeXやPowerPointなど掲載先で管理し、画像に重複して埋め込まない。グラフ内には軸名・単位・目盛り・必要な凡例など、データの読み取りに直接必要な情報だけを残す。
推奨する共通スタイル
- 背景は白、文字・軸・主要目盛りは黒〜濃い灰色とする。影、3D、グラデーション装飾、不要な枠や背景色を加えない。
- 標準のFigureサイズは `5.8 × 3.8 inch` とする。基本フォントサイズは `9 pt` とし、軸ラベル、目盛り、凡例を原則として同じサイズにする。
- 図内の日本語フォントは Noto Sans JP を標準とする。英数字は DejaVu Sans をフォールバックとし、数式にはMatplotlibのDejaVu Sans系mathtextを使用する。
- 枠線は `0.8 pt`、データ線は `1.4 pt`、マーカーは `4.2 pt` を標準とする。
- 目盛り線は下辺と左辺だけに置き、外向き、長さ `3.5 pt` とする。数値ラベルはプロット領域の外に置く。
- グリッド線は原則として横方向の主要目盛りだけに、薄い灰色で表示する。値の読み取りを助けない場合は省略してよい。補助グリッドや補助目盛りを密に入れすぎない。
- 凡例は原則としてプロット領域の外側上部に置き、枠を付けない。短い線グラフでは、末端に系列名を直接書く方法もよい。
- 図内タイトルは設けない。図番号、題名、キャプションはLaTeXやPowerPointなど掲載先で管理する。
- プロット領域を広く確保し、凡例、軸ラベル、目盛りラベルに必要な余白だけを設ける。複数グラフではプロット領域の寸法、ラベル位置、表記法を可能な範囲で揃える。
- 掲載先またはユーザーの指定がある場合はその指定を優先する。スライドなど標準値では判読性を確保できない用途では、最終表示サイズに合わせてFigureサイズ、文字、線、マーカーを調整する。
軸範囲と端点の扱い
- 定義域と観測範囲を区別する。 実験設計上の範囲、物理的・数学的に許される範囲、今回観測された最小値・最大値は同じとは限らない。軸範囲は原則として最初の二つに基づいて決め、単に観測値の最小・最大を自動採用しない。
- 範囲が確定している数量軸は端点を枠線に合わせる。 例：割合が 0〜100%、設定した負荷が 0〜12、ホップ数が 1〜8 の場合、比較目的に支障がなければそれぞれ 0〜100、`0〜12`、`1〜8` に固定する。軸の範囲を -0.5〜12.5 のように広げることを標準動作にはしない。端点の目盛りも表示する。
- 整数・離散値の軸も数量軸として扱える。 0, 1, …, 12 が測定条件として定義された整数値であれば、0と12を軸の端に置いてよい。ただし識別子や名称のようなカテゴリでは、値の数値的な距離に意味がないため等間隔のカテゴリ軸を用い、棒・マーカーの表示に必要な左右の余地を設ける。
- 端点の測定点は欠けさせない。 0 または 12 の測定点が枠線上に重なること自体は問題ない。ただしマーカーやエラーバーがクリッピングで欠ける場合は、軸範囲を不用意に広げず、マーカーのクリッピング設定、描画順序、輪郭線などを調整する。枠線との重なりによって点が見分けられない場合は、その部分の識別性を優先して例外的に小さな余白を許容する。
- 範囲が不定な軸には適切な余白を設ける。 応答時間、通信量など上限が実験設計から決まらない量は、データ点やエラーバーが枠線と密着しないよう、読みやすい目盛り値に合わせて範囲を取る。ゼロ起点を必要とする図ではゼロを保つ。
- 部分拡大は明示する。 0〜12 全域では変化が読みにくい場合、拡大図・別パネル・軸範囲を明示した図を併用してよい。比較図間で軸範囲が異なる場合は、その違いが分かるようにする。
- Matplotlibでは自動余白に任せない。 範囲が確定した軸には ax.set_xlim(0, 12)、`ax.set_ylim(0, 100)` などを明示する。単に ax.margins(0) とするだけでは、データ範囲と定義域を混同する場合がある。`clip_on=False` はプロット外への描画が意図的かつ欠けないことを確認して使う。
配色規則
- 色は意味を区別するために用いる。同じ系列・条件・手法には図をまたいで同じ色を使う。デフォルトの循環色を無批判に使わない。
- まず色数を少なくする。単一系列は濃い青または黒、主要系列と比較系列は青と橙、基準・補助系列は灰色を基本とする。
- 推奨色（Okabe–Itoパレットに基づく）：青 #0072B2、橙 #E69F00、青緑 #009E73、赤橙 #D55E00、紫 #CC79A7、空色 #56B4E9、黄 #F0E442、黒 #000000。白背景上で低コントラストな黄や薄い空色は、線幅・輪郭・他の符号化を調整するか避ける。
- 色覚多様性とモノクロ印刷に対応するため、色だけでなく 実線／破線／点線、`○／□／△／×` などを併用する。見分けにくい赤と緑の二色の対比を避ける。
- 提案手法と複数の既存手法の比較など、研究上の主役が明確なときに限り、主役に強調色を割り当て、その他を灰色または近い色系で控えめにする。ただし比較に必要な系列まで見えなくしない。
- 色の選択はデータ型に合わせる。 区分の識別には離散色、大小の連続値には知覚的に単調な連続カラーマップ（例：viridis）、正負や基準からの偏差には中点が明確な発散型カラーマップを使う。連続量の表現に虹色・jetを安易に使わない。ヒートマップにはカラーバーと値・単位を付ける。
グラフ形式と線の意味
- 散布図： 独立した測定値の位置・相関・分布を示す。根拠のない線で点を結ばない。
- 折れ線グラフ： 時間や連続条件に沿う推移を示す場合に使用できる。点間の直線は値を補間しているように見えるため、未測定区間に連続性を仮定できるか確認する。時系列でも欠測区間を無条件につながない。
- 近似・回帰曲線： 理論、仮説、妥当なモデルに基づき描く。見た目だけを滑らかにするスプライン補間を根拠なく適用しない。必要なら推定方法を記す。
- 棒グラフ： 件数やカテゴリごとの量・集計値の比較に用いる。原則ゼロ起点。標本数の少ない実験や分布が主題の場合には、個々の点・箱ひげ・バイオリン等の併用も検討する。
- 箱ひげ図等： 中央値、四分位範囲、外れ値等の定義を明確にする。箱ひげ図だけでは分布が十分に表れない場合、点を重ねる。
- 誤差表示： 複数試行や推定の不確実性を示す場合、目的に応じてエラーバー・区間帯を描く。SD、SE、95%信頼区間など何を表すかと試行数 n を明記し、互いに混同しない。
- 比較用の複数図： 共通尺度で比較する場合は同じ軸範囲・単位・色対応を揃える。異なる範囲を使う場合はその違いを読み手が認識できるようにする。
論文図とスライド用グラフ
- 論文・レポート： 印刷時の最終サイズで軸値と統計情報が判読できることを優先する。図番号・題名・詳細な実験条件はLaTeXなど掲載先のキャプションに記し、画像には埋め込まない。
- スライド： 遠方からの視認性を優先して文字・マーカー・線を大きくする。主要な比較対象数と目盛り数を絞る。図のタイトル・結論・詳細な実験条件はスライド側で管理し、グラフ画像に埋め込まない。ただし軸名・単位・系列の意味は省略しない。
- 同じデータでも論文用とスライド用で再レンダリングする。単純拡大だけで済ませない。
実装・出力・検査
- 作図には原則Pythonを用い、標準ライブラリはMatplotlibとする。 ax.set_title() と fig.suptitle() は原則使用しない。 データの加工・集計には必要に応じてNumPy、pandas等を使用する。ユーザーが別の作図環境を指定した場合はその指示を優先する。
- 完成した各グラフは、ベクター形式とラスター形式の両方で必ず出力する。 標準の組み合わせは同一の図から生成した SVG と PNG とする。論文・投稿先の要件に合わせて PDF も追加できる。
- SVGは原則 svg.fonttype = "none" とし、テキストを編集可能な文字として残す。表示環境にNoto Sans JPがない場合は代替フォントで表示され得るため、配布先で表示を検査し、必要に応じてPDFへのフォント埋め込みや文字のアウトライン化を検討する。
- ベクター形式は、文字や線が拡大しても粗くならないことを優先する。ただし、ヒートマップや大量の点など、必要に応じて部分的なラスター化を許容する。フォントの埋め込み・互換性は掲載先の要件に従う。
- PNGは原則300 dpi以上で保存し、スライドや印刷など使用目的に応じて寸法・dpiを調整する。dpiだけで画質が決まるわけではないため、最終的なピクセル数も確認する。
- 2形式では、データ、軸範囲、系列、色、ラベル、凡例などの内容を一致させる。ファイル名は同じベース名とし、例として latency_comparison.svg と latency_comparison.png を用いる。
- savefig 時は描画内容と余白が欠けないようにし、両形式を確認する。画面上での表示だけでは完成扱いにしない。
- 元データと作図用Pythonスクリプト、設定、単位換算を再現可能な形で保管する。手元で再生成できるときはスクリプトも成果物に含める。
- 最終掲載サイズに縮小して確認する。カラー表示、モノクロ表示の両方で比較系列と主要な結論を読み取れるか検査する。
作図後チェックリスト
1. 軸が何を表すか、単位があるか。
2. 数値ラベルと目盛りの対応が明確か。重複や過剰桁数はないか。
3. 測定点、線、回帰、誤差のそれぞれの意味が判別できるか。
4. 配色・線種・マーカーが系列と一貫して対応し、モノクロでも読めるか。
5. 軸の定義域と観測範囲を区別したか。確定した端点に余計な余白がなく、端点のマーカーが欠けていないか。非ゼロ起点・対数尺度・集計方法が誤解を招かないか。
6. エラーバーや帯の統計的定義と標本数が分かるか（使用している場合）。
7. 凡例とラベルがデータに重なったり切れたりしていないか。
8. 最終掲載・投影サイズで読めるか。SVGとPNGの両方が生成され、内容が一致しているか。
9. 画像に図番号・タイトル・キャプションを重複して埋め込んでいないか。掲載先で説明する情報と、図内に必要な軸・凡例を切り分けたか。
10. データ変換、補間、除外などの操作が明示され、再現可能か。
